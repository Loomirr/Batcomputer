# Batcomputer 1.1 — Beta 2

This beta collects the general tool improvements and fixes since **1.1.0-beta.1**.
Thanks to everyone testing builds and reporting problems, especially with imported bodies,
animations, icons and character voices.

## Refreshed Beta 2 packages — October 7

The downloads on this release include updater repairs; this is still **1.1.0-beta.2**.
If you already installed Beta 2, download the refreshed **Batcomputer-update-win-x64.zip**
once and follow the manual update instructions below. The older updater cannot offer a
replacement with the same version number. Beta 1 and earlier supported clients can update
normally with **Stable + beta** enabled.

- Update checks now name the checked channel and explain when a newer beta is excluded
  by Stable, rather than implying no newer release exists. Switching channels checks again.
- Fixed helper/runtime loading from deeply nested installation folders using extended-length
  Windows launch paths. Update scheduling now confirms that the helper actually started,
  reports failures before exit, and keeps the Update center responsive during preparation.
- Verified published Beta 1's install/restart flow, the revised helper at a previously failing
  path depth, and 39 updater regression checks. Settings and project data were preserved.

## Animation Studio and Explorer

- Browse readable character animation sets in a searchable tree, see current replacements,
  and choose your cooked clips or base-game animations inline. Reset individual targets to
  their donor without changing other characters.
- Find editable drafts and cooked versions in **Your animations**, with filters and assignment
  badges. Editing a draft keeps the assigned cooked version until you cook and assign its replacement.
- Start an editable variation from readable native/imported motion. Import cooked packages or
  actions from a saved Blender file directly in the studio. Blender actions must already use
  LOTDK's body rig; this is not automatic retargeting or gameplay-notify import.
- Select several bones, apply bulk transforms and key edits, and save named bone groups such
  as Arms or Breathing. These are organizational groups, not overlapping animation layers.
- Improved dense-animation playback and timeline control reuse reduce unnecessary UI work
  without removing keys from the clip.
- Draft combat hit windows on the timeline with start, contact and end frames. These are
  **preview planning markers**, not automatic damage events. Unsupported timing drafts are
  blocked from being cooked as ready-to-use attacks.
- Add animation voice cues, including **Play on empty swings** for attack efforts. Native voice
  triggers, chance and cooldown still apply.
- Cook validation checks native bone mapping and decoded poses, replacement skeletons and
  normal/additive compatibility. ACL loop-compressed endpoints no longer produce false errors
  for their intentionally omitted duplicate sample.

## Character voices

- **Character Voice Studio** adds searchable native voice slots, categories and assignment
  filters, an imported WAV library, waveform playback and clearer saved/build-profile status.
- Ctrl/Shift-select several slots to assign one recording, silence them or restore their
  original voice. Partner-speaker dialogue remains read-only.
- Adjust assigned recordings with the volume control; peak limiting protects boosted output
  and source WAVs remain unchanged.
- **Use for builds** selects a saved profile. **Build mod** encodes and packages that profile
  into character-local routing; selecting it alone does not cook or install anything.
- Fixes localized media staging, long encoder scratch paths, inherited profile ownership and
  conflicting Vorbis setup identities. Native character voices and sound assets are not replaced.

Native playback requires a configured vgmstream decoder; custom voice builds require the
supported encoder tools. The menu covers discovered native slots, not every possible scripted
dialogue trigger. New story dialogue and mission permissions are not provided by this workflow.

## Icon Studio and emblems

- Create and assign a selected icon or all four character icons together.
- Independent cameras for menu, left, right and suit slots use revised template-based positions,
  with corrected left/right destinations and separate suit-tile framing.
- Revised lighting balances blue and warm rims on the same power scale, adds a white/key-light
  control and improves material/color response. The viewer still approximates the game shader.
- Export/import camera and lighting settings as JSON templates. Earlier presets load with a
  neutral key-light default. Smaller windows retain accessible controls and footer actions.
- Generated icon cooks use the playable target's actual mod namespace, avoiding errors when
  its folder differs from the saved project ID.
- Corrects native character-emblem SDF encoding. Use transparent source art with transparent
  cutouts and margins; the native shader supplies the white fill and black edge. The HUD name
  backplate is separate and cannot be erased with emblem transparency.

## Character suits and shared assets

- **Rebase from character** refreshes selected saved sections, including abilities, held items,
  equipment, voice and animations, while retaining suit identity and sections you keep specific
  to that suit. This is explicit rebasing, not automatic live inheritance.
- Combined mods reuse compatible family assets while preserving distinct authored variants.
  New child suits reference the included character's unchanged textures instead of copying
  PNGs and cooking duplicate texture packages.
- **Base character textures** and **Suit + base character textures** filters expose read-only
  shared textures for reuse; the material picker includes them too. Import a suit-local PNG
  when you want a separate texture. Older copied recipes are retained.
- Preserves cached helper-ability identities during creation/rebasing and checks for missing
  or duplicate grants when replaying a saved gameplay graph.

Keep child suits and their character definition in the same mod. Save, rebuild and reinstall
after rebasing; changing the recipe does not update an already installed mod.

## Held items, materials and equipment

- Reworked native/extra held-item menus and OBJ workshops offer in-place imports, slot-based
  material assignment, a **Your materials only** filter, reference visibility and frame controls,
  actual dimensions, import-unit helpers and shared move/rotate/size gizmos.
- Alignment updates reuse preview geometry. Importing preserves visibility choices and the
  original model's size instead of silently reframing or hiding it.
- Edit supported native held-item visuals and animation-spawned static items in character-local
  clones. Conditional extra-prop visibility and verified toggle bundles preserve native hand
  priorities; compatible input observers retain native Focus takedowns.
- Remove or restore equipped gadgets without merely hiding their meshes; matching runtime and
  menu/upgrade entries stay synchronized.
- Select another compatible face-animation Blueprint separately from the character's face materials.
- Material Forge adds native dummy texture choices, inherited surface/detail controls and a
  cape-fuzz reduction preset. Supported shader UV selectors are distinguished from preview-only UVs.
- Fixes custom-model preview mount paths, material resolution and packed material handling.

## Body, takedown and donor fixes

- Imported CharacterMesh0 bodies now retain their native donor's synchronized-animation
  compatibility metadata. Rebuild existing validated imports to apply this repair; reimporting
  the FBX is not required just for this metadata change.
- Warns when recognized native takedown grants do not match the body's Minifig/Smallfig family.
  Use **Ability workshop → Takedowns** to choose a matching native pair where appropriate.
- Short, tall and native-rig custom-body test cases passed takedowns in-game. This does not
  retarget arbitrary rigs, align every custom proportion or establish the cause of every older mod's issue.
- Supports native playable metadata whose optional UI data is omitted by default while retaining
  the selected gameplay donor. Genuinely missing authored UI dependencies still block a build.
- Cape/glide adapters follow the donor's native traversal parents, including shared DLC sets.
  The guides clarify the complete matching cape/glider pair workflow for glide-only donors.

## Abilities

- Independently assign native clue/trail tracking and configurable passive healing in the
  ability picker, with individual edit/remove controls and saved build replay. They are separate
  choices, not a required combined ability set.
- Utility settings and the actual target namespace survive Ability workshop editing and saving.
- Corrects sheathed forward-movement selection in angle-based blend spaces and supports
  context-specific animation pairs without disconnecting existing action variants.

## Updating

Enable **beta releases** in Updates, then **Check for updates → Download → Restart now**.
Your saved Stable/Beta preference survives manual installs too. If an older copy says it is
up to date, open **Settings & recovery → Stable + beta**, then check again. Older helpers
that cannot start from a deeply nested folder may need the complete portable folder moved
to a shorter path before updating; they cannot receive this fix until the update is installed.
Beta 1 installations can use the smaller version-specific patch when their reusable files
match; other versions or modified installations use the complete ZIP fallback.

For a new installation or manual update, download **Batcomputer-update-win-x64.zip** and
extract the whole ZIP. Close Batcomputer and back up your projects before merging it into
an existing installation. Do not copy only the EXE; the `app/` folder is required. Settings
and editable workspace data are not included as replacement files in the update.

This is a beta; **1.0.0 remains the stable release**. Unreal Engine 5.6 and Blender are still
needed for their respective cooking/import workflows. Game assets, Oodle and LOTDKExpanded
are not bundled. Experimental paired animations, cross-family gameplay and effects still
need their own in-game checks before you share a mod.
