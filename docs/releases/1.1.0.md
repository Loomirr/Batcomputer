# Batcomputer 1.1

**Stable release · 1.1.0 · October 11, 2026**

Batcomputer 1.1 brings the animation, voice, icon and suit-inheritance tools from the 1.1 betas into the stable channel, alongside new vehicle-workshop, build-feedback and body-matched combat fixes. Private character abilities, private test packs and game-runtime mods are not part of this release.

## New since Beta 3

- **Body-matched dodges:** the Ability workshop now has a separate **Dodges…** selector for Minifig/Batman and Smallfig/Robin behavior, including paired enemy vaults. It preserves the original input and ability level without changing attacks, equipment or takedown choices. Short-Batman and tall-Robin test suits passed in-game testing. Use the separate **Takedowns…** selector when that family also needs changing, then rebuild your mod.
- **Clearer builds and ZIP exports:** resizable progress windows show the current phase, content item, elapsed time and recent activity, with a copyable log. ZIP compression runs in the background and reports files/bytes. A completed archive replaces the previous one only after success. Modern result dialogs show full selectable paths, Copy path and Open folder actions.
- **Suit inheritance warnings:** Check mod identifies gameplay sections that changed in a saved parent after a suit's last inheritance review. Refresh the desired sections explicitly; appearance and icons can remain suit-specific. No automatic overwrite of intentional overrides.
- **Vehicle workshop:** Ctrl/Shift-select several parts to move/rotate together or apply supported uniform group scaling, with grouped undo. Material assignments refresh in place without resetting the camera or reloading the viewer. Toybox and launcher meshes use corrected preview messages and queued loading, with an optional all-part-mesh view.
- **Vehicle seats and outlets:** repairs seated-preview loading and uses the native bike idle sequences for bike previews. Disabled second boost outlets no longer block builds; their saved placements are ignored with a warning and retained for later use. Turning off two outlets now means one active outlet, including donors that natively use two.
- **Materials and attachments:** your own materials and face materials can be used as the base for a new editable copy. Exact native parts use the drag-and-drop path again. Regular cape recipes are selectable through the existing guarded cape workflow instead of being incorrectly disabled; cape/glider compatibility checks still apply.
- **Current game data:** checks detect outdated extracted assets/mappings and guide a refresh before building. Corrects the bike summon-rig identity and mesh redirection. The published mappings download path remains stable.
- **Import safeguards:** the 2022 bike body importer has an explicitly experimental, bounded wheel-mount-placement option; other bones, hierarchy, rotation and scale must still match the native rig.

## Highlights since stable 1.0

- Animation Studio: editable timelines, bone gizmos, multi-bone selection, named bone groups, native-rig Blender actions and cooked-animation imports; Animation Explorer and a reusable clip library.
- Character Voice Studio: searchable slots, WAV libraries, waveform playback, batch operations and character-local voice routing, with voice staging and encoding fixes.
- Icon Studio: individual or all-four-icon creation/assignment, per-slot cameras, revised lighting, corrected left/right destinations, shareable JSON settings and correct output ownership.
- Character suits: section-based rebasing and reuse of compatible textures, animations and other included base-character assets rather than unnecessary duplicates.
- Held-item and material workflows: removal/restoration, custom appearance and supported toggle bundles, improved workshops and inherited detail/UV controls. Tracking and passive healing are independently assignable abilities, not a required bundle.
- Custom bodies and animations: restored synchronized-animation metadata, explicit height-matched takedown choices and validation of equivalent skeletons by bones, hierarchy and reference transforms rather than asset name alone. Incompatible rigs and additive modes remain blocked.
- Updated compatibility checks, native cape/glider handling, emblem encoding and build diagnostics. See the [Beta 1](1.1.0-beta.1.md), [Beta 2](1.1.0-beta.2.md) and [Beta 3](1.1.0-beta.3.md) notes for the detailed history.

## Updating

Open **Updates → Check for updates**. Both **Stable** and **Stable + beta** can receive 1.1.0; it supersedes 1.0.0 and the 1.1 betas. This release uses the complete updater ZIP, including the bundled Windows x64 .NET runtime, for every supported starting version.

For a manual install/update, download **Batcomputer-update-win-x64.zip**, close Batcomputer and extract the entire archive. Keep `app/` beside `Batcomputer.exe`. Do not use an older `update-from-…` patch ZIP as a standalone installation. Back up projects first. An older updater failing to launch from a deeply nested folder may need a shorter installation path or this manual full-ZIP update.

The editor update does not install game mods, rebuild existing mods, refresh game extracts automatically or replace the separately installed LOTDK UE4SS framework. Following a game update, refresh mappings/extracted assets and rebuild affected mods.

## Known limits

- Whole-vehicle runtime resizing is blocked: parked and driving sizes could disagree, and the experimental hook was associated with a crash report. Set **Legacy size %** to 100%, resize/reimport the source model and review placements instead. Saved projects are not silently rescaled.
- Rider previews use native idle poses but do not simulate every in-game adjustment, animation or IK correction. Launcher previews show rest geometry, not deployment.
- The two cross-height dodge test suits are verified in-game; arbitrary custom rigs, changed graphs and every donor combination are not. Always test ground dodges, enemy vaults, brute slides and takedowns in your own mod.
- Imported rigs and summon models retain their documented experimental limits. Combat hit-window drafts are planning data, not newly authored game damage events.
- The existing transitive ImageSharp dependency still produces NuGet vulnerability advisories. This release does not resolve or claim to resolve those advisories; only import trusted source files.
