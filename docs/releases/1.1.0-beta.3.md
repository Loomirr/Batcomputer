# Batcomputer 1.1 — Beta 3

This is a focused fix for custom-animation builds rejected with **"Replacement motion targets a different skeleton."** It includes the features and updater repairs from Beta 2.

## Animation compatibility fix

- Previously, the build check required the replacement's Skeleton asset path to match the donor's exactly. A separately named copy of the same rig could be rejected even when its bones and reference pose matched.
- The check now accepts equivalent skeletons after verifying bone names, parent relationships and reference transforms. Matching bones can have a different serialized order.
- Different bone sets, hierarchy or reference poses still fail validation. Normal, local-space additive and mesh-space additive animations remain distinct; this fix does not disable those safeguards.
- Skeleton mismatch messages now identify both assets and the specific mismatch instead of reporting only a different path.

After updating, open the existing project and run **Check mod**, then **Build mod**. An equivalent imported skeleton does not need to be renamed or reimported solely for this fix. If a mismatch remains, use the new diagnostic to repair or retarget the clip for its donor. Renaming a genuinely incompatible skeleton is not a repair.

## Verification and limits

A controlled cooked animation using a separately named, identical skeleton reproduced the rejection in Beta 2 and passed the corrected check. Validation left the asset files unchanged. Fourteen new regression cases cover equivalent rigs, bone order, incompatible rigs, reference transforms and additive-mode safeguards.

The original reported third-party animation files were unavailable, so this is a verified correction to the false-rejection case, not a claim that every reported import is compatible. This update does not retarget animations or change their in-game motion.

## Updating

Choose **Settings & recovery → Stable + beta**, then **Check for updates → Download → Restart now**. This is a new version, **1.1.0-beta.3**, so Beta 2 users can receive it through the updater; no same-version manual refresh is required.

Matching Beta 2 installations can use the smaller version-specific patch. Other supported versions or installations with changed reusable files use the full ZIP fallback. Settings and editable workspace files are not replaced by the update.

If an older helper cannot start from a deeply nested installation folder, close Batcomputer and move the complete portable folder to a shorter path before updating, or use the full ZIP. That older helper cannot receive its launch-path repair until the update is installed.

For a manual update, close Batcomputer, back up your projects and extract the entire **Batcomputer-update-win-x64.zip** into the existing installation. Keep the `app/` folder with the launcher; do not copy only the EXE.

This remains a beta. **1.0.0 is still the stable release.**
